# Support, security and contributions

- **Questions / onboarding / feature requests:** open a GitHub issue in [QualityRag](https://github.com/cyrillesaxo/QualityRag/issues). Include SDK, language/runtime version, reproduction instructions, actual versus expected verdict, and sanitized test data.
- **Public bugs:** add a minimal reproducible case to `conformance/v0.1.json` or the appropriate SDK unit tests.
- **Sensitive security issues:** do not open a public exploit report or paste tokens, client data, personal records or credentials into issues. Use GitHub's private vulnerability reporting if enabled; otherwise contact the maintainer privately through a channel they explicitly publish. No security-response SLA is promised.
- **Pull requests:** keep contract changes language-neutral, add tests, run relevant CI, and document changes to decision semantics and limitations.
- **Scope of assistance:** source-built experimental libraries, not a managed SaaS or certified policy engine.

Contributions should preserve `REFUSE` precedence, avoid upgrading unknown evidence to PASS, and never claim source authenticity from an origin string.
